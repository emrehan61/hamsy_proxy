# v0.4.2

Fixes session loss and "Invalid form authenticity token" errors when browsing through HTTPS interception.

Browsers such as Chrome can send cookies in separate HTTP/2 header fields. Hamsy now joins those fields with `; ` when forwarding to an HTTP/1.1 server, preserving the session cookie alongside analytics and other cookies. This follows RFC 9113 section 8.2.3.

The fix applies both during capture and when capture is paused. Response `Set-Cookie` fields remain separate. Regression tests cover an actual HTTP/2 client, TLS interception, and an HTTP/1.1 origin.

Existing users can run `hamsy update`, restart Hamsy, and reload any login form opened before the update.
