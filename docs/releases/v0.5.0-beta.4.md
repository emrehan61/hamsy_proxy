# Hamsy 0.5.0-beta.4

MCP connections now start Hamsy automatically when the configured API is not
running. Users no longer need a separate terminal to start capture first.

- Reuses existing Hamsy instances and serializes concurrent agent startups.
- The background app survives individual agent disconnects.
- Startup binds to loopback, leaves system proxy and certificate trust settings
  alone, and preserves saved settings and other instances' recovery markers.
- Private runtime logs keep MCP stdout clean. Startup failures and port conflicts
  report an actionable error instead of replacing another service.
- `--data-dir`, `--proxy-port`, and `--api-url` configure startup.
- `--no-auto-start` preserves connect-only operation; `--print-config` remains
  side-effect free.
- `hamsy mcp --stop-app` authenticates and stops only the MCP-started instance.

Applications still need to send traffic through the proxy to be captured.
The 14 existing tools, including live/HAR regex search, remain available.
Reconnect MCP after installing this beta. Branch builds do not publish a stable
release; download the workflow artifact for your platform.
